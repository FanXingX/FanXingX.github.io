1.2习题总结

  1. 不属于多道操作系统的基本特征的是顺序性 多道操作系统没有顺序, 只有一定的优先度.

  2. 实时操作系统不要求资源利用率高, 而要求安全可靠, 及时相应, 以及快速处理

  3. 允许多个用户进行交互分时操作系统

  4. 单处理器进程之间只能够串行。只有多处理器系统才能让进程并行执行
  5. 实时操作系统有实时性的要求，因此必须在规定时间内处理完来自外部事件
    而分时操作系统不要求在规定时间（调度时间/周转时间）内必须完成某一事件，只是时间到了之后，分时操作系统会自动切换到下一件事情。
    批操作系统不要求在响应时间内处理完同一个任务。

中断和异常的概念

  1. 中断和异常的定义

    中断

    • 称为外中断 是指来自CPU内部执行指令外的事件

    • 时钟中断

      时钟中断是外中断，因为它是由CPU外部的时钟部件在固定时间间隔内产生的，并且中断的处理并不直接依赖于当前执行的指令

    • 输入/输出(I/O中断)

    • 硬件造成的中断(除了缺页)

    异常

    • CPU执行内部事件造成的中断, 一般在指令最后的一个周期(中断周期)检测.
    • 程序的非法操作码(用户态执行内核态指令)
    • 地址越界
    • 内存溢出
    • 缺页中断
    • 运算(ALU)溢出
    • 专门的陷入指令

  2. 中断和异常的分类

    外中断

    • 可屏蔽与不可屏蔽中断

    • 不可屏蔽一般指掉电

      在收到中断时，CPU 会把当前那条指令执行完，然后转移到中断处理程序，返回后执行的是当前的下一条指令。

    内中断

    • 故障 fault

      • 非法操作码

      • 缺页故障

      • 除数为0故障

      • 运算溢出故障

        ​ 交给中断程序处理后故障返回到指令执行的这一条语句? 还是下一跳语句?

        ​ 操作系统接收到中断信号后，会根据中断向量表中对应的中断处理程序来处理这个中断异常，具体处理过程包括保存现场、处理中断、恢复现场等步骤。

        有可能能够恢复，处理后返回原程序原指令继续执行(产生 fault故障指令会重新执行)。

        如：`Page Fault缺页故障，General Protection系统保护

    • 自陷 trap

      • 事先的安排

        执行引起陷阱的指令后产生的异常，处理后返回原程序从下一条指令开始继续执行。如 syscall 系统调用。

        按照我的理解，软件中断算是一种 trap，如 INT 3 产生断点异常。

    • 终止abort

      • 不可恢复的中断, 直接终止程序的运行

        不可恢复。不会获得产生异常的精确位置，也不允许异常程序继续执行。中断处理程序通常用于记录信息，处理后不会返回，而是关闭程序或系统。如：Machine Check 自检未通过，Double Fault二重故障

        P.S. Triple Fault三重故障 不属于 abort 异常的范畴，它没有对应的中断向量号，而是直接挂掉

  3. 中断和异常的处理过程

中断处理程序与子程序调用的比较:

  1. 前者是独立的, 后者有明显的主从关系
  2. 中断的产生是随机的, 而后者通过调用指令CALL引起的
  3. 前者可能有专门的电路来实现, 后者由软件程序的处理过程实现
  4. 入口地址的区别
  5. 俩者都需要保护程序计数器PC的内容, 前者由中断隐指令完成, 后者由CALL指令完成
  6. 响应中断时,能对多个中断响应进行裁决优先级

​ 系统调用的处理过程

  1. 将系统调用号和参数压入栈中; 接着执行实际调用的指令, 然后执行一个陷入指令, CPU 从用户态转为核心态.
    再由硬件和操作系统保护中断现场. 将PC, PSW, 通用寄存器 中的内容保存(压入栈中)
  2. 分析类型, 转入相应的系统调用程序(根据系统调用入口表找到入口地址).
  3. 处理完后, 在系统调用处理子程序执行结束后, 恢复被中断的CPU现场(还原现场), 然后从原来的位置继续往下执行.

用户执行陷入指令的时候, 相当于将CPU的使用权主动交给操作系统内核态程序 CPU则会 从用户态进入核心态

准备实模式下的中断向量表以及中断服务程序

系统在初始化过程中的操作大致可以分为以下几步

  • 启动BIOS，准备实模式下的中断向量表以及中断服务程序
  • 从启动盘加载操作系统程序到内存
  • 内核初始化，系统调用

A正确。中断向量表是用于处理各种硬件中断和异常的数据结构。在操作系统初始化过程中，需要创建中断向量表并初始化其中的中断向量。中断向量表将每个中断的唯一编号映射到相应的中断处理程序地址，以便在发生对应的中断或异常时，能够正确地进行处理。

B错误。文件系统的根目录是文件系统的最顶层目录，包含着文件和子目录的层次结构。根目录通常是在文件系统格式化或创建的过程中创建的，而不是在操作系统初始化过程中创建。操作系统初始化时可能会加载和初始化文件系统，但根目录本身通常是在文件系统创建过程中创建的。

拓展: 对任何一个普通进程来讲，它都会涉及到5种不同的数据段。归纳一下进程对应的内存空间中所包含的5种不同的数据区都是干什么的。

  1. BSS段：BSS段（bss segment）通常是指用来存放程序中未初始化的全局变量的一块内存区域。BSS是英文Block Started by Symbol的简称。BSS段属于静态内存分配。

  2. 数据段：数据段（data segment）通常是指用来存放程序中已初始化的全局变量的一块内存区域。数据段属于静态内存分配。

  3. 代码段：代码段（code segment/text segment）通常是指用来存放程序执行代码的一块内存区域。这部分区域的大小在程序运行前就已经确定，并且内存区域通常属于只读, 某些架构也允许代码段为可写，即允许修改程序。在代码段中，也有可能包含一些只读的常数变量，例如字符串常量等。

  4. 堆（heap）：堆是用于存放进程运行中被动态分配的内存段，它的大小并不固定，可动态扩张或缩减。当进程调用malloc等函数分配内存时，新分配的内存就被动态添加到堆上（堆被扩张）；当利用free等函数释放内存时，被释放的内存从堆中被剔除（堆被缩减）

  5. 栈(stack)：栈又称堆栈， 是用户存放程序临时创建的局部变量，也就是说我们函数括弧“{}”中定义的变量（但不包括static声明的变量，static意味着在数据段中存放变量）。除此以外，在函数被调用时，其参数也会被压入发起调用的进程栈中，并且待到调用结束后，函数的返回值也会被存放回栈中。由于栈的先进后出特点，所以栈特别方便用来保存/恢复调用现场。从这个意义上讲，我们可以把堆栈看成一个寄存、交换临时数据的内存区。

  6. 全局的未初始化变量存在于.bss段中，具体体现为一个占位符；全局的已初始化变量存于.data段中；而函数内的自动变量都在栈上分配空间。.bss是不占用.exe文件空间的，其内容由操作系统初始化（清零）；而.data却需要占用，其内容由程序初始化，因此造成了上述情况。

  7. bss段（未手动初始化的数据）并不给该段的数据分配空间，只是记录数据所需空间的大小。

  8. data（已手动初始化的数据）段则为数据分配空间，数据保存在目标文件中。 数据段包含经过初始化的全局变量以及它们的值。BSS段的大小从可执行文件中得到 ，然后链接器得到这个大小的内存块，紧跟在数据段后面。当这个内存区进入程序的地址空间后全部清零。包含数据段和BSS段的整个区段此时通常称为数据区。

    1. 从阻塞队列中找到PCB
    2. 将其从阻塞队列中移除
    3. 将`PCB插入就绪队列, 等待调度程序调度

  2. 线程的基本概念

    1. 引入线程的目的提高多道程度技术的并发效率, 提高资源利用率和吞吐量.
    2. 最直接的理解是轻量级进程
    3. 进程是CPU分配资源的最小单元. 线程是CPU调度的基本单位.(线程自己不拥有资源)
    4. 一个进程的内部拥有众多线程. 若在进程内部的线程切换消耗的资源少.

  3. 线程与进程之间的比较

  1. 调度比较. 进程内的线程的调度切换消耗小. 进程间的切换消耗大
  2. 并发性. 不同进程间的线程也能够并发执行.
  3. 拥有资源. 进程是CPU分配资源的基本单位. 线程间共享内存地址
  4. 独立性.
  5. 系统开销.
  6. 支持多线程处理器. 单线程进程只能在一个CPU上运行. 而多线程进程能分配给多个CPU上执行’
  1. 线程的属性, 状态, 与控制方式与进程无异
  1. 线程的实现方式:

  1. 用户级线程ULT

    • 内核意识不到线程存在

    • 用户级线程的调度时间依旧按进程调度为最小单位

      优点:

      • 不需要转换到内核态
      • 线程间的调度可以用户自己编写

      缺点:

      • 进程被阻塞时, 所有的线程阻塞
      • 由于进程意识不到CPU存在, 不能发挥多CPU优势,不能把多个线程分配给多个CPU执行

  2. 内核级线程KLT

    • 内核根据线程控制块对线程进程控制

      优缺点与用户级线程相反

  3. 组合方式

结合用户级线程与内核级线程, 由操作系统的线程库提供管理和创建线程的API

  1. 用户空间中没有内核支持的库

  2. 支持内核级别的库

    pthreads是支持内核级别的线程库

  1. 多线程模型

  1. 多对一
    • 多个用户级线程映射到一个内核级线程
  2. 一对一
    • 每一个用户级线程映射到每一个内核级线程
  3. 多对多
    • 将$n$个用户级线程映射到$m$个内核级线程 且 $n \ge m$

若为单级中断处理程序,则去掉子图中的开与关中断两部分.

中断屏蔽字是描述“中断屏蔽”状态的一组“二进制信息”。

作用‌：中断屏蔽字用于在提出中断请求之后，CPU不予响应的状态。它常用于在处理某一中断时防止同级中断的干扰或在处理一段不可分割、必须连续执行的程序时防止任何中断事件的干扰。
